# Activity execution audit and General Entrance routing

Inspected actual StreamManager calls on 2026-10-12. Only SLEEPING and TALKING
were classroom-only. PHONE USE and EATING already executed on every camera.
An enabled detector does not imply a confirmed activity or a visible label.
Thresholds and existing rules were not changed in this update.

## Actual paths

| Activity | Source and rule | MediaPipe required | General Entrance before → after | Classroom | Gate / reason |
| --- | --- | --- | --- | --- | --- |
| SLEEPING | `classroom/student_state.py`, SleepingDetector: sustained EAR < 0.20, or head-down without visible face; default 15 seconds | Yes | No → Yes, opt-in | Yes | Formerly only `if is_classroom: classroom_monitor.analyze(...)`; now also reused by PersonActivityAnalyzer on general cameras |
| TALKING | `classroom/student_state.py`, TalkingDetector: MAR standard deviation >= 0.035 over up to 30 samples, at least 8 samples, sustained default 8 seconds | Yes | No → Yes, opt-in | Yes | Same routing as sleeping |
| EATING | `behavioral/person_activity.py`: three complete wrist approach/withdrawal cycles within 20 seconds | Yes, face and pose | Yes → Yes | Yes | StreamManager activity sample block has no classroom gate |
| PHONE USE | `vision/detector.py` COCO 67 + `behavioral/person_activity.py`: phone near raised wrist, unambiguous person, 2 seconds and 3 hits | Yes, pose; plus YOLO | Yes → Yes | Yes | Same ungated activity block |
| RUNNING | `behavioral/movement.py`, MovementAnalyzer: computed displacement/time > 15 and at least three velocity samples | No | Yes → Yes | Yes | AgentBus tracks publication and Celery analysis run for all cameras |
| SUDDEN ACCELERATION | `behavioral/movement.py`: recent-three velocity mean / earlier-five mean > 3, positive baseline, at least five stored samples | No | Yes → Yes | Yes | Same movement path |
| LOITERING | `behavioral/loitering.py`: duration >= 300 seconds, movement radius <= 0.05 | No | Yes → Yes | Yes | Same agent/Celery path; no classroom gate |
| RESTRICTED AREA | `behavioral/zone_checker.py`: person center in an active camera-specific polygon | No | Yes → Yes | Yes | Requires configured active restricted-zone polygons, not camera.zone_type=restricted |

Paths are relative to `ai-engine/` except the agent/Celery callers below.
Movement's constant is named `RUNNING_SPEED_PX_PER_FRAME`, but actual code divides
displacement by elapsed seconds. This audit records that implementation without
changing it. Existing loitering coordinate assumptions are likewise unchanged.

## Gates and configuration

`StreamManager._camera_loop()` reads `camera.zone_type` at stream initialization.
Only `zone_type == "classroom"` instantiates/calls ClassroomMonitor. The repository
has no `classroom_enabled` switch in this execution path. ClassroomConfig supplies
sleeping/talking durations, expected students and teaching zone; existence of that
record does not turn analysis on for a general camera. ClassroomMonitor loads it
once and supports the existing refresh_config mechanism.

`ENABLE_ACTIVITY_ANALYSIS_ON_GENERAL=true` now enables the existing sleeping and
talking rule classes for `zone_type == "general"`. It is set in root `.env` and
`backend/.env`, with a default/example of true. False disables this added general
sleep/talk path. Previously installed phone/eating and movement rules continue
running, preserving their prior routing. Other zone types do not inherit the new
sleep/talk path. A stream/backend restart reloads the routing configuration.

The general branch creates only SleepingDetector and TalkingDetector state, using
their existing defaults of 15 and 8 seconds. It never constructs ClassroomMonitor,
AttendanceAnalyzer or FacultyEngagementAnalyzer and never calculates CAI or calls
`_persist_classroom_metric` / `_publish_classroom_metric`. Missing-student and low
class-attention banners are not generated by this branch. No automatic general
sleep/talk alerts or consequential decisions were added.

## Cadence and track attachment

- YOLO/tracker process every `FRAME_SKIP=3` raw capture frames.
- Phone/eating and new general sleep/talk sample on processed frames at a minimum
  interval of `ACTIVITY_ANALYSIS_INTERVAL_SECS=0.75`. Actual spacing can be longer
  when CPU/capture is slow. Each eligible person's crop shares one FaceMesh+Pose
  pass; existing per-camera FacePoseAnalyzer singleton loads models once.
- Classroom sleep/talk and metrics remain every 30 raw frames, provided that frame
  is also a processed frame. That frame forces activity sampling and supplies the
  same landmarks to ClassroomMonitor, avoiding a second MediaPipe pass.
- Movement/loitering/restricted-area calls remain every 30 raw frames:
  `StreamManager` → `AgentBus.publish("tracks")` →
  `agents/behavior_agent/agent.py::_on_tracks()` → rule analyzers. The parallel
  existing Celery path is `backend/app/services/tasks/ai_tasks.py::analyze_behavior`.
  Agent-produced overlay events are written to camera behavior_state in Redis.
- Every rule emits `event(type, severity, track_id)`. StreamManager attaches
  phone/eating/general-face events through overlay-cache source `activity`, class
  events through `classroom`, and agent results through `behavior` (Redis poll
  every 0.25 seconds). `BehaviorOverlayCache.attach()` merges into that same
  track's `behaviors`; QR identity is attached afterward and FrameAnnotator draws
  the JPEG. Max two person labels and camera banners remain unchanged.
- General sleep/talk, phone and eating state is cleaned when a track disappears;
  fresh streams create fresh state. No second tracker, per-frame database query,
  or model instance was added.

## Diagnostics and validation

`ACTIVITY_DEBUG` stays false by default. The verification backend was launched
with a temporary process-environment override of true. Diagnostic lines include
camera ID/name/zone, analyzer routing, MediaPipe execution and per-track candidates.
ClassroomMonitor logs its own actual sleeping/talking candidates at its unchanged
cadence; activity log entries defer those two classroom statuses to that monitor.
Logs: `logs/backend-general-activities.err.log`. A normal backend launch restores
the configured debug setting; remove the temporary override if launching manually.

Observed General Entrance log: zone=general, general_sleep_talk_enabled=True,
classroom_metrics_enabled=False, MediaPipe_executed=True, track_id=1. Sleeping,
talking, eating and phone-use candidates were false in sampled frames. This
verifies execution, not a live positive action trial. No detections were fabricated.

Native live check: General Entrance running with a fresh valid 640x480 WebSocket
JPEG, 1.99 processed FPS and 0.2-second frame age. Classroom retains its source
`http://172.28.170.74:8080/video` and still reports connection timed out; its live
pipeline could not be exercised. Its controlled capture integration test passes.

Backend CPU over five seconds: 17.67 CPU seconds / 5.02 wall seconds on eight
logical processors, approximately 44% of total machine CPU. This includes the
existing backend workload, not only the activity rules. No reliable before/after
comparison was available because port 8000 refused connections before startup.
The new sleep/talk state updates reuse existing samples and add no inference pass.

Tests: **77 passed** across person_activity, behavior_overlays, qr_identity,
retired_zigzag and stream_recovery. Added coverage for real sleep/talk confirmation
on the general branch, opt-out, independent cleanup, phone/eating on that branch,
and controlled capture routing for classroom/general enabled/general disabled.
The general capture tests assert ClassroomMonitor is never instantiated or called
and classroom metric persistence/publication are never called. QR and max-label
regressions pass. Frontend code was unchanged; no new frontend build was needed.
